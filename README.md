# vercel-store

A [vercel.store](https://vercel.store)-style storefront as a TDK landscape: Vue 3 frontend + Hono BFF in one `store` stack. Built on the same strategy as [tdk-thor-storefront](https://github.com/tdk-landscape/tdk-thor-storefront): TDK owns the landscape, a hosted commerce backend owns the catalog, the BFF is the only thing the browser talks to, and there is no local database.

Here the hosted backend is the public vercel.store storefront. `bun run sync:catalog` snapshots its products into `services/store/vercel-bff/data/catalog.json`; the BFF serves that snapshot, keeps carts in memory, and hands checkout back to vercel.store. No credentials needed.

## Run

| Option | Command | URL |
| --- | --- | --- |
| Bun (Bun + Git only) | `bun install && bun run dev:local` | http://127.0.0.1:3350/storefront-web/ |
| TDK (Docker, Tilt, TDK CLI) | `cp .env.example .env && tdk up store` | http://app.vercel-store.localhost:8080/storefront-web/ |

Deep links mirror vercel.store: `#/products/triangle-wavy-tee?color=Black&size=2XL`.

`tdk up store --dry-run` previews routes without starting containers.

## BFF routes

Through TDK these live under `http://api.vercel-store.localhost:8080/api/vercel-bff`; in Bun mode at `http://127.0.0.1:4350`.

| Route | Purpose |
| --- | --- |
| `GET /health`, `GET /context` | health, catalog snapshot info |
| `GET /products?search=` | product summaries |
| `GET /products/:handle` | options and variants |
| `POST /cart`, `GET /cart/:id` | create / read a bag |
| `POST /cart/:id/lines`, `DELETE /cart/:id/lines/:variantId` | add / remove a line |

## Develop

```sh
bun run check      # tsc + vue-tsc
bun run test       # BFF (bun test) + web (vitest)
bun run sync:catalog   # refresh the snapshot from vercel.store
```

## Limits

- Carts live in BFF memory and are lost on restart.
- vercel.store exposes no public cart permalink, so "Proceed to Checkout" opens the product page of the first line on vercel.store.
- Do not edit `.autogenerated/` or `.tdk/.tdk-out/`; TDK regenerates them.
